## TaskContract v1

### 当前值类型一致性修正

SDK的accepted/proves现在拒绝NUL和无效UTF-8，accepted还校验所有证据状态与
来源，包括关闭验收要求的阶段。独立C++的判定移入私有src并复用同一核心，
公开类型布局不变，头文件不引用SDK。此前仅检查引用非空，会把无效引用当成
可用证据；JSON接口原已拒绝这类输入。本次修正使值类型也不会接受它们。

主目录六个任务文件同步核对、三个APP重建通过。完整libai24项，独立C++静态/
动态各11项，Python7项契约、实际JNI契约和C++ APP当前证据/人工审核/外部修改/
重启回归通过。测试含过长UTF-8编码、代理区、越界码点、截断编码、NUL、合法
Unicode及关闭要求后的无效证据；仅剩头文件类型的消费方须重新链接封装库。
整体仍按上表核对，不以这些测试代替其它目标验收或Windows/设备端运行证据。

循环结束、生成完成、构建通过、测试通过、人工接受是独立事实。
SDK 仅设置 loop_finished / loop_outcome，其余证据默认 unknown，accepted 默认 false。
原 status=completed 保持兼容，但不能用来推断验收通过。

每个证据包含 state、revision、authority、reference：

- generation：completed；build/tests：passed；review：accepted。
- 其余状态：unknown / failed / not_required；review 另支持 rejected。
- generation/build/tests 必须由 host 提供，review 必须由 human 提供。
- revision 必须与非空 artifact_revision 相等，reference 必须非空。
- 模型说明不能作为执行证据；修改任何文件后宿主必须更新成果版本。
- requirements 四项默认 true。分析任务等不需要某项验收时，由宿主显式声明 false；
  模型不能修改验收要求。
- 只有 loop_outcome=completed 且所有要求都有当前版本可信证据时 accepted=true。
- 版本号为 1；尚未提供报告签名或存储证明。authority/reference 由受信任宿主写入；
  不能把此评估器或证据修改接口暴露为无需授权的模型工具。

所有桌面完整绑定使用 CodingService.call 的 tasks.evaluate 操作；C 使用 libai_coding_call。
输入为契约对象，输出包含 accepted、checks、unmet。评估器无副作用，不启动编译、
不接受变更，也不检查 reference 对应的报告是否存在。

轻量 SDK 可使用 task_contract_t / 独立 C++ TaskContract；C ABI run JSON 同样保留契约。
其他语言通过 JSON 读取字段，尚未提供各语言独立的证据构造/修改 API。
后续需接入真实构建、测试及审核记录，不能仅凭 JSON 声称第一项目标完成。

- tasks.revision 在受限项目目录扫描源码，虚拟合并待确认写入/移动/删除/目录操作。

## 持久化运行总耗时

C++ HTTP 状态与共享 CodingService runs.get/list 从审计开始/结束时间派生 elapsed_ms。
时间来源标记 unix_seconds，elapsed_resolution_ms=1000；不把秒级历史记录伪装为精确
毫秒或单调时钟测量。运行中采用当前 Unix 时间；终态只使用记录结束时间，重启不增长。
缺失或倒退的时间、溢出返回 elapsed_available=false，elapsed_ms=0。
stream_progress.elapsed_ms 仍表示单次模型请求，latency_ms 仍表示模型请求累计耗时。
此派生不改变持久化格式，不补造构建/测试/审核证据；更精细持久计时仍需后续实现。
